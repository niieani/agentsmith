# Generate self-contained scope-aware skills

Skills use the same renderer as instructions: packs may enable them, selected packs provide reusable contributions keyed by slot name, and includes flatten private partials into the emitted skill. One contribution is inserted into every enabled skill declaring that slot; a contributing pack never names or depends on its consumers. This lets a project select its own `tracker` pack once and embed those instructions into several shared skills. The generated public Skill Name is separate from its qualified source identity, and agentsmith rejects duplicate visible names across any effective scope chain even where a harness defines precedence. This stricter rule prevents different harnesses from exposing different or ambiguous behavior and avoids relying on unreliable runtime skill chaining.
