# Add a generic harness and place each skill once per harness

Harness adapters now model what each harness reads, not only where agentsmith writes. A new `generic` harness targets the shared `.agents/` convention: `~/.agents/skills` globally, `<scope>/AGENTS.md` and `<scope>/.agents/skills` in projects, and no global instruction file because no harness reads `~/.agents/AGENTS.md`. `codex` keeps `$CODEX_HOME/AGENTS.md` globally, writes no global skills because Codex marks `$CODEX_HOME/skills` deprecated, and writes project skills to `<scope>/.codex/skills`. `claude` is unchanged. This supersedes the destination tables of [Model validated harness scopes](2026-07-13-model-validated-harness-scopes.md); its decision to expose only validated first-class adapters stands. The discovery facts behind it are in the [harness discovery reference](../../website/docs/reference/harness-discovery.md).

Codex reads `.agents/skills` and `.codex/skills` and de-duplicates skills by path only, so one skill written to both loads twice and a plain `$name` mention then selects neither. Each adapter therefore declares its write roots and every root it reads, and placement is computed from that data: a skill enabled for a set of harnesses is written to the fewest roots that let each of those harnesses read it exactly once, preferring roots read by more of them. Harness-specific skill content renders only into a root read by exactly that one harness. The duplicate-visibility lint compares skills by the harnesses that read their roots, so planned and unmanaged skills in `.agents/skills` and `.codex/skills` collide for Codex.

## Consequences

- A skill enabled for `generic` lands once in `.agents/skills` and serves Codex too. Codex-specific skill-slot content consumed by it is an error, because Codex reads the common copy.
- A skill enabled for `codex` but not `generic` lands in `<scope>/.codex/skills` with Codex content. Globally there is no such root, so it is an error that suggests enabling the skill for `generic`.
- Harnesses that resolve to the same instruction file share one artifact. The project `AGENTS.md` uses the `codex.md` template variant when `codex` is selected, otherwise `generic.md`, otherwise `default.md`; common snippets render first, then `generic`, then `codex` snippets.
- Profiles and scopes accept `[harness_skills.<harness>]` tables with `enable` and `disable`, applied after the harness-neutral skill lists. The harness must be selected.
- When a project `CLAUDE.md` would equal the generated `AGENTS.md` beside it, agentsmith writes `@AGENTS.md` instead. Claude Code guarantees that import never loads `AGENTS.md` twice whatever its **Project instructions** setting. Omitting `CLAUDE.md` was rejected: any `CLAUDE.md` above the working directory, or a user setting, disables Claude Code's `AGENTS.md` fallback. `claude_import_agents_md = false` opts out.
- `instructions/generic/` and `skill-slots/harnesses/generic/` become harness-specific directories, and `generic.md` a template variant.
