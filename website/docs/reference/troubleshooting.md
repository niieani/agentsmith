## Project output is dirty

agentsmith will not overwrite a modified, staged, conflicted, untracked, or ignored destination unless it still holds exactly what agentsmith last wrote there. Review the file and either commit the intended version, restore the generated content, or move it out of the generated path. There is no project `--force` option.

A generated skill whose folder already holds files agentsmith did not write, such as a skill the repository commits, is refused with an error naming the folder. Rename the generated skill, or adopt the folder with `asmith project adopt --skill NAME`.

## Global output is unmanaged or changed

`global sync` and `global generate` exit with code 5. Run `asmith global diff` to see the difference, then choose:

- To keep text you added at the very top or bottom of a global `AGENTS.md` or `CLAUDE.md`, run `asmith global adopt`.
- To keep a copy of the file but let generation continue, run `asmith global generate --on-modified=backup`. Review the `*.agentsmith-<timestamp>` file backup, or skill backups under `~/.agents/agentsmith/backups/`, afterwards.
- To discard the changes and take over the paths, run `asmith global generate --force`. This updates the external hash state after writing.

## Adoption refused

`asmith global adopt` changes nothing when any modified artifact cannot be adopted:

- **Edits are not strictly before or after the generated content.** Move the change into the Source Repository by hand, then restore the file or run `global generate --on-modified=backup`.
- **Skill artifacts are never adopted.** Back them up with `--on-modified=backup` and merge the change into the skill source.
- **No stored generated content exists.** The artifact was last generated by an agentsmith version that did not keep content. Back it up or force once; later edits can be adopted.
- **The snippet path is not ignored by Git.** Add `*.local.md` to the Source Repository's `.gitignore`. A tracked or untracked snippet would make the Source Repository dirty and block `global sync`.

## Exclusive mode reports unmanaged skills

With `exclusive = true`, `lint`, `generate`, and `sync` exit 5 and list every skill directory agentsmith did not write. For each one, choose:

- **Keep it and manage it with agentsmith**: `asmith global adopt --skill NAME` (or `asmith project adopt --skill NAME`). It moves into the Source Repository (or the project's `.config/agentsmith/skills/`) and is generated from then on.
- **Keep it, managed by another tool**: add its directory name, or a glob such as `vendor-*`, to `exclusive_allow`.
- **Remove it**: run with `--on-modified=backup` to move it to the backup folder, or delete it yourself.

`adopt --skill` reports `Several different unmanaged skills are named NAME` when two roots hold different directories with that name. Delete the copy you do not want, then adopt again.

## Clean refuses a modified artifact

`asmith global clean` and `asmith project clean` exit 5 and remove nothing when an artifact changed since agentsmith generated it. Keep the change somewhere first, or choose:

- `--on-modified=backup` keeps a backup (`<name>.agentsmith-<timestamp>`, or the skill directory under the backups folder) and then removes the artifact.
- `--force` removes it without a backup.

For a project, `git diff` shows what changed in tracked files. After `project clean --yes`, commit the deletions it leaves, or run `project generate` to recreate the files.

## Template declares a reserved slot

`prepend` and `append` are added implicitly at the very top and bottom of every instruction artifact. Rename a template slot that uses either name.

## Global status reports a problem

`asmith global status` exits with the failed run's exit code, or with 6 when no run is recorded or the last one is older than `--max-age`. The printed error and warnings come from `~/.agents/agentsmith/status.json`. Fix the cause and rerun `asmith global sync`.

## Sandbox home problems

- **`home is not an existing directory`**: create the directory named by `home` in the machine config, or fix the path. Relative paths resolve against the config file's directory.
- **`global status` reports no recorded run for a sandbox**: pass the sandbox config with `--config`. Without it, status reads `~/.agents/agentsmith/status.json` in your real home.
- **Git asks for an identity or a key inside a sandbox**: it should not, because Git keeps your real `$HOME`. Check that the variables you run asmith with (`HOME`, `GIT_CONFIG_GLOBAL`) point at your real configuration.

## Source Repository is not clean

`global sync` exits with code 3. It rejects tracked, staged, conflicted, and nonignored untracked source changes. Commit, stash, or remove them before syncing. Ignored local source such as `*.local.md` is allowed.

## Git pull cannot fast-forward

`global sync` exits with code 4. It uses only `git pull --ff-only`. Resolve divergence manually in the Source Repository, then rerun the command. agentsmith will not merge or rebase on your behalf.

## Missing slot contribution

A `required-slot` received no snippet from the selected packs. Add a contribution under the matching pack slot directory, select the intended pack, or change the directive to an optional `slot`.

## Contribution targets an absent slot

A selected pack has content for a slot the template or enabled skill does not declare. This is usually a mismatched template/pack combination or a misspelled slot name.

## Skill name collision

Two skills visible from the same working location share a public name. `asmith project explain` shows generated skill sources. Rename or disable one source, or remove the conflicting unmanaged skill. agentsmith does not silently choose a winner.

## Codex override shadows generated context

An `AGENTS.override.md` that agentsmith did not write sits next to a generated `AGENTS.md`. Codex reads it instead of `AGENTS.md`, so generating there would be misleading. Move its content into a `*.local.md` snippet in a project pack and delete the file; agentsmith then writes its own `AGENTS.override.md` with the shared layer plus your snippet.

## Personal files and settings

- **`settings.local.json is not valid JSON`** or **`is tracked by Git`**: agentsmith adds `claudeMdExcludes` entries to `<project>/.claude/settings.local.json` and refuses to edit a file it cannot parse or one Git tracks, since the entries hold this machine's paths. Fix the JSON, or run `git rm --cached .claude/settings.local.json` and ignore it.
- **`NOTICE personal-input-skipped`**: there is no machine config, so a Source Repository pack, skill, template, or partial was left out. Shared inputs still render. Configure a machine with `asmith global init` to include them.
- **`never writes a repository's committed files`**: with `upstream`, a personal file such as `CLAUDE.local.md` is committed in that repository. agentsmith will not replace it; remove `upstream` or ask the repository to stop committing it.
- **`WARNING prepare-script-kept`**: `project init --prepare` found a `prepare` script that does something else and left it unchanged. Chain `&& asmith project generate` to it by hand.

## Symlink destination or ancestor is not allowed

agentsmith never writes through a symlink inside the folders it manages, such as `~/.claude`, `~/.codex`, `~/.agents/skills`, or a project's `.agents/` and `.claude/`. If you link one of those to a dotfiles repository, generation stops instead of writing into the link's target. Replace the link with a real directory and let agentsmith own its contents.

Symlinks above those folders are fine. Your home folder, the project, and the Source Repository may be reached through a symlinked path, such as macOS `/var` or `/home` on Fedora Atomic; agentsmith resolves those roots before comparing them with what Git reports.

## Size budget warning

Use `asmith project explain` or `asmith global explain` to inspect artifact and effective-chain sizes. Reduce duplicated material, move reusable workflow detail into an on-demand skill, or intentionally raise the corresponding budget.

## Harness limit reported

A diagnostic such as `WARNING codex-project-doc-bytes` or `ERROR claude-import-depth` means a generated file or skill crosses a limit the harness itself enforces. The message names the file or scope, the size, the limit, what the harness does past it, and the `budgets.<harness>.<key>` that sets it. See [harness limits](/reference/configuration#harness-limits) for the full table.

- **`codex-project-doc-bytes`**: Codex reads at most 32 KiB of project instructions by default, summed over every directory from the repository root to where it starts. Move detail out of the shared ancestors into a nested scope or a skill. If you raised `project_doc_max_bytes` in Codex, set `[budgets.codex] project_doc_bytes` to match.
- **`claude-instruction-file-lines`** (notice): the `CLAUDE.md` with what it imports is longer than Claude Code recommends. It still loads; trim it when you can. Notices never fail a run.
- **`claude-on-demand-file-chars`**: a nested `CLAUDE.md` is loaded only when Claude Code works in that folder, and then only its start is read. Shorten it or move detail into a skill.
- **`claude-import-depth`**: an `@import` chain goes deeper than four hops, so the deepest files never load. Import them from a shallower file.
- **`codex-skill-name-chars`**: Codex will not load a skill whose name is longer than 64 characters. Rename the skill directory and its `name`.
- **`*-skill-description-chars`**, **`*-skill-listing-*`**: descriptions are truncated, or the listing of all skills at that scope, global ones included, is over the harness's budget. Shorten descriptions, disable skills a harness does not need with [`harness_skills`](/reference/configuration#per-harness-skills), or remove unused global skills. Claude's listing budget scales with the context window; raise `[budgets.claude] skill_listing_tokens` if yours is larger.

## Diagnose without writing

```sh
asmith project lint
asmith project explain --json
asmith project diff
```

These commands are safe to use while investigating because they do not write generated artifacts.
